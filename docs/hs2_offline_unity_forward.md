# HS2 offline renderer — Unity built-in forward generator (2026-10-20)

Component: `src/render/hs2pipe/unity_forward.py` with `unity_math.py`, `unity_shadows.py`,
`unity_light_hull.py`, `scene_state.py` (and the forward-rule / shadow-bounds modules listed in §6).
It turns one exported **scene state** into the values Unity 2018.4.11f1 writes for one camera
render and the pass plan of that render. Siblings own the executor and `frame_program.py`,
`shader_library.py` (variant and pass selection, cbuffer packing), CTAA (`ctaa.py`), DHH SSS,
Liquid, PPv2/MSVO. Architecture contract: [hs2_offline_renderer_architecture.md](hs2_offline_renderer_architecture.md).

No game was launched. Nothing was fitted. Every rule is either transcribed from the installed
engine binary, taken from Unity's built-in shader source, or marked **capture_observed**.

## 4 Scene-state input (game exporter field list)

The authoritative list is `scene_state.FIELDS`; `scene_state.field_table_markdown()` renders it.
Read every `per_render` field in a `Camera.onPreRender` callback of **that** render (the bridge
and CTAA change the camera between the 16 renders; CTAA sets the projection in `OnPreCull`).
Floats may be given as `"0x%08x"` bit strings; matrices are 16 floats in Unity memory order.

Additional requirements found during the recovery:

- `cameras[].previous_frame_last_mv_render`: the non-jittered projection and `worldToCameraMatrix`
  of the **last motion-vector render of the previous frame** for that camera (source of
  `_PreviousVP`; 2018.4 has no public accessor).
- Runtime QualitySettings must be exported: the installed asset (level 4 "Quality": 4 cascades,
  400 m, StableFit off = CloseFit) differs from the capture (1 cascade, 120 m) — a plugin or the
  game config changes them at runtime.
- `lights[].local_to_world` exactly as `Light.transform.localToWorldMatrix` (shadow basis).
- `SystemInfo.graphicsMemorySize` and `SystemInfo.maxTextureSize` for the shadow-map size clamp.

Still missing from the 2026-10-20 probe export (needed for the next paired run):

1. `Light.transform.localToWorldMatrix` (plus `position`/`rotation`) for every enabled light:
   `_WorldSpaceLightPos0` and the shadow basis of 0x6a4400 (light X/Y/Z axes).
2. `Camera.transform.position` (exact) — `_WorldSpaceCameraPos` currently comes from
   `cameraToWorldMatrix` column 3, which matched, but is not the API Unity reads.
3. Per camera render: the culled visible renderer list and the shadow-caster list of each
   shadowed light (or enough to run the recovered culling), and `Renderer.bounds` of all renderers
   (present) — inputs of the two shadow MinMaxAABBs.
4. `ReflectionProbe.defaultTexture` identity and `ReflectionProbe.defaultTextureHDRDecodeValues`
   at render time (reflection constants).
5. Shader-global `_Time` read inside `OnPreRender` (or the TimeManager values behind it).

## 5 Gaps (explicit, not substituted)

1. **Shadow acceptance.** The cascade fit, the close-fit hull and both MinMaxAABBs are
   transcribed (`unity_shadows`, `unity_light_hull`, `unity_shadow_bounds`), but
   `unity_WorldToShadow`, the shadow-caster VP, `unity_LightShadowBias` and `_WorldSpaceLightPos0`
   are not yet byte-checked: the paired export lacks the light `localToWorldMatrix`. The caster
   set itself (light shadow culling, `PrepareShadowedLight` 0x67eb30 / `CalculateShadowCasterCull`
   0x679140) is not transcribed (`shadow_cull_visible` is an input), nor are terrain/Umbra paths.
2. **Pass plan binding.** `unity_forward_plan.plan_camera_render` takes `cull / sort_draws /
   classify_lights` callables; `unity_forward_rules` implements the transcribed rules on
   RenderObjectData/RenderNode inputs (`extract_render_objects`, `sort_draws(draws, camera, ros,
   nodes, opaque=…)`, `classify_lights(obj, lights, quality)`, `calculate_culling_parameters`). The
   adapter from scene-state renderers to those records, the motion-vector object list and the
   ForwardAdd emission are not written yet, so the draw list of the paired capture is not
   compared. `draw_cbuffers` (shadow-copy cbuffer bytes for a planned draw) is implemented and tested.
3. **CRT transcendental calls** (`cosf`, `sinf`, `powf`, `fmod`) are taken as correctly rounded
   (`crt_trig`, `crt_pow`). Every captured value that depends on them matched.
4. **Transform SIMD paths** (`CalculateInverseGlobalMatrixNoScale`, `CalculateGlobalPositionAndRotation`)
   are not transcribed; the exporter supplies `worldToCameraMatrix` / `localToWorldMatrix`.
5. Reflection-probe selection/blending and HDR decode; LightProbeProxyVolume parameters;
   `_MotionVectorDepthBias` writer; unused-cascade matrix writer; StableFit fade centre;
   Trilight/Flat ambient; colour temperature; point/spot shadows; `unity_CameraWorldClipPlanes`
   (`SetClippingPlaneShaderProps` 0x692590 not transcribed).
6. Programs without an installed export (`AIT/Skin True` body, `AIT/Clothes True`,
   `Shader Forge/hair_07`, `Skybox/MyCubemap`) have no Unity cbuffer layout here, so their
   built-in variables are not compared; the shader-library sibling owns their recovery.
