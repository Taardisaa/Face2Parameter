# Optional ABMX semantic modes: consumer migration proposal

This is a read-only implementation plan, not a completed migration. The frozen compiler (`0f721b16…`) and existing training/card/renderer/optimizer code are unchanged. The user-modified `scripts/hs2_optimize_ingame.py` and untracked `docs/proposal.md` were read, not edited. The proposal's claim that photo likeness is already recovered is a user design premise, not new validation evidence.

## Explicit modes before changing consumers

| Proposed explicit mode | Position meaning | Execution and limits |
|---|---|---|
| `installed_abmx_stateful` | Actual installed Apply recurrence, historical radius/direction and flags | Requires source-bound persistent state, clean/boundary policy and actual or declared call sequence. No inferred settle=count. |
| `first_clean_abmx_target` | `t = ((normalize(p_native)*r_history)*L)+d`, preserving first clean logical Apply | Physical Length=1, Position=`t-p_native`; scale/rotation retained. Current compiler supports four named bones and selected clean branches only. New saved runtime proof is one head2/mixed59/four-patch case, not arbitrary 30-bone coverage. |
| `native_radial_target` (design only) | `t = p_native*L+d` | Also physical Length=1, Position=`t-p_native`. Intentionally uses current native radius rather than historical radius; matches the legacy offline position formula by definition, and is **not** vanilla first-Apply parity when `r_history != norm(p_native)`. No implementation or runtime certificate yet. |
| `legacy_static_offline_diagnostic` | Current unconditional offline `p*=L; p+=d` | Preserve for historical diagnostics; never silently promote its output to installed runtime parity. |

Missing mode/context must produce a clear refusal for runtime-certified use. An unsupported bone or branch must not fall back to static ABMX. Native-only prediction with `ab=None` remains separately usable. Each result should retain original logical parameters, executed physical patch, exact mode revision, target/rounding errors, bounds, source profile, full59/base, history/asset/assembly hashes and quality decisions. A saved physical patch does not uniquely recover its original logical Length/offset; retain the logical sidecar rather than treat physical card re-reading as a lossless logical round trip.

## Full 30-bone and invalidation gap

`META_DATA_LIST` in `src/face_data_utils/utils.py` contains 30 bones; four have the current stable-lowering contract. The remaining 26 include face-up/low/chin-low, cheek-low, all eye groups, nose and mouth groups. They need per-bone existence/topology and local-space verification on the actual base, baseline/history cache behavior, exclusions/additional modifier/restore/short-length classification, first-target and repeated-Apply proof, native perturbation coverage, and full multi-mesh surface/quality/visual validation. Do not assume mirrored names have identical runtime behavior or let missing cached bones silently disappear (`_fk_world` currently skips absent names).

First implement a four-bone optional consumer with unsupported names rejected. Then extend coverage in bounded anatomical groups (parent/child chin, bilateral cheeks, nose, mouth, eyes) while retaining all30 ordering/masks and independent observations. Eye coverage requires the actual eye/lash surfaces and expressions as well as o_head. The current fullhead quality gate is insufficient: root reported newly introduced cross-mesh intersection pairs despite passing o_head self-quality. There is no character-ready result.

Invalidate the compiled context after any base/head/asset/bindpose/topology change, any native59 or sampling-profile change, source DLL/IL/native predictor revision, recollected historical radius/direction, baseline TRS change, nonclean flags, changed actor/observer source, additional/scene/exclusion branch, unobserved writer, or unsupported capture state. New modifier IDs alone may be accepted only after a **new actual guard** establishes exact persistent numerical history and predicted native baseline. Restore, desmile, and mirrored edits must happen before target freezing. Never silently rebuild a logical target from a candidate's observed after state.

## New metadata guard revision

`tools/abmx_stable_lowering/strict_metadata_guard.py::verify_execution_guard_v2` runs the immutable v1 numerical/source guard first, then adds source-bound reflected modifier type and exact typed cursor invariants. `observed==completed==last_sequence` is an explicitly supported serial-complete prefix policy, not a generic reentrant observer theorem. Zero-prefix is permitted. The optional complete stopped trace independently verifies the actual recorded prefix; no count=settle or UTC-age rule is introduced.

The saved lowered_v2 identity snapshot can pass a new **posthoc** guard audit; its original live collection still used v1. The old accepted wrong-type/counter gaps and frozen reports remain preserved. A future consumer should explicitly select and record this new revision rather than rewrite old compiler artifacts.
